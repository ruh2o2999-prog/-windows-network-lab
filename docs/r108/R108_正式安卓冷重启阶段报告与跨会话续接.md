## 1. 真实继承基线与安全边界
- 正式插件为原 **V0.4.58 MV2**，ZIP `370557` 字节、93 项、SHA256 `32219f852321aea68843acfac91a33c86be2563c4f4a609988fed109d7edc479`，本 R108 阶段未修改任何正式插件业务源码。
- 历史完整工程 R103 及 R107 冻结包继续继承；V2.2 R01～R40、F01～F15、T01～T54，以及 UX、R77～R107 的原编号、原失败原样保留。统一执行《四套软件研发规范 V8.9.1》，G0—G5 的实证门限不能降低。
- 真实环境：Github Actions Ubuntu24.04 KVM / Android 11 API30 Google APIs x86_64 / 官方 Kiwi 137.0.7337.0。属于 Android 虚拟宿主真实 APK 安装操作，不冒称三星手机实体机验收。
- 公共 GitHub 实验仓库 `ruh2o2999-prog/-windows-network-lab`，**隔离分支** `kiwi-r108-android-restart-persistence` 未合并主分支。原 MV2 仅通过每次新生成的 RSA3072 临时证书、CMS AES256 加密提交**密文**到公共隔离分支；公有仓库不含明文正式源代码、私钥。
- 本阶段不使用 `pm clear`。真正测试的是 `adb shell am force-stop com.kiwibrowser.browser` 后重新启动；该动作不是清除数据，也不是低内存 OOM、采集中突然崩溃或长时间休眠的等效验证。

## 4. 研究得到的源码与操作路径
- `capture-store.js` 使用 IndexedDB `KiwiCaptureEvidence_R26` 版本3；`background.js` 执行恢复并通过 `CAPTURE_TASK_LIST` 列出；`panel.html` 的 `details#capture-history` 与 `panel.js` 的 `renderCaptureHistory()`、`exportHistoricalTask()` 可从持久化索引读取原任务 Trace、Blob、CDP 文件，**源码可用不代表实际二次导出通过**。
- 在真实扩展管理页 XML 提取 `ID: [a-p]{32}`；同一正式插件完整面板 `chrome-extension://<id>/panel.html` 可使用，**比嵌入网站的狭窄侧栏可靠**。
- 折叠区打开与 UI 列表成功出现的证据见第二轮 `r108_history_open_7.xml/png`、`r108_history_after_async_load.xml/png`。XML 中多任务历史列表 `scrollable=true`，但离屏元素 `bounds=[0,0][0,0]`。正确下一步是分离**外层主文档**与**内层历史 `source-list`**，先把包含原任务的第三条列表滚到可点击区域，再在其单独 `source-item` 父节点内点击「导出」，严格禁止全局第一个「导出」。
- 本轮 GitHub 新增：`kiwi-r108-lab/r108_restart_history.py`（真实 ADB/UI），`kiwi-r108-lab/r108_offline_recovery_parity.py`（双真实 ZIP 严格核对），`kiwi-r108-lab/test_r108_offline_recovery_parity.py`（7 个正反例）。**离线对账器正反例通过**，但没有真正的后重启 ZIP 输入时，R108-ZIP-01 不可 PASS。
- 成熟备用路线：Android 官方 UiAutomator `UiObject2.scrollUntil` / 按明确滚动容器定位文本；在授权本地测试器中直接按已知资源 ID/DOM `scrollIntoView` 而不改正式产品源码；通过页面 native Find-in-page 定位目标历史摘要。路线均应先做独立受控验证，再正式实测，不凭建议销项。
