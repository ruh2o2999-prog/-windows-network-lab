# Kiwi R110｜V8.12 统一规范接续与历史导出索引冲突修复

日期：2026-11-13。阶段：候选版本（未发布）。产品：原 Kiwi Browser Android MV2 扩展，未改浏览器、未另做 APK。

## 1. 本轮唯一业务缺口

- 原编号：R109-INDEX-01（历史导出 `00_本次观察结果.txt` 文件名冲突）；相关 R108-EXPORT-01、R108-ZIP-01，以及旧 R07/R17/R26/T17/T37，均继承，不因本轮 L2 验证自动销项。
- 原始验收：Kiwi Android 冷重启后能打开同一 captureSessionId 的已结束任务，实际下载历史 ZIP 并由 ADB 回读；要求 ZIP CRC、请求事件集合和 36 份真实 CDP 正文 SHA-256 与重启前的实际导出逐项一致。
- 业务阻断层：**产品源码**；不是测试器/宿主/加密传输。证据来自 R109 GitHub Android `43224942632`：原生面板加载、CDP 历史按钮点击均成功，但原版弹出“索引控制文件冲突：00_本次观察结果.txt”，历史 ZIP 未生成。

## 2. 已证实的根因、最小修复

- 冻结正式包：V0.4.58（370,557 字节）SHA256 `32219f852321aea68843acfac91a33c86be2563c4f4a609988fed109d7edc479`。
- `panel.js` 的 `exportHistoricalTask` 手动加入 `files.push(toFile('00_本次观察结果.txt', ...))`，随后调用 `KiwiEvidenceIntegrity.finalize`。
- `evidence-integrity.js` 为根目录保留该摘要文件名并明确拒绝任何预先占用——两者发生确定性冲突。
- 仅将前者替换为 `files.push(toFile('History/历史任务摘要.txt', ...))`；`evidence-integrity.js`、ZIP、CDP 存储和 UI 均保持原封不动。
- 候选版本：V0.4.59-rc1（仅测试用），候选包 SHA256 `caa0e128b1d1a9d185f0d18ea6af39d36a63fa2abeb587acab2f8dc5ff0720e9`。93 个 ZIP 成员中只有 `panel.js` 与 `manifest.json` 改变；正式 V0.4.58 没有覆盖。

## 3. L2 实验与证据

- 调用**原本的整个** `exportHistoricalTask` 函数、原版 `evidence-integrity.js` 与 `zip-store.js`，非自行复写算法。
- 输入：R107 在真实 Android Kiwi 中采集的 36 份 `Network.getResponseBody` 二进制响应（9 份 HTTP 404），保留原始 CDP index 及 SHA256；只对浏览器消息层、下载保存层做 Node 测试替身。
- 旧版同输入：`EXPECTED_FAIL`，准确抛出 `索引控制文件冲突：00_本次观察结果.txt`；ZIP 未保存。
- 修复候选同输入：生成 50 项 ZIP、74,572 字节，CRC PASS，36/36 实际 CDP body SHA256 一致，索引 `indexed`、0 个缺口、0 个来源摘要不一致。
- 这只能证明 L2 模块与 ZIP 集成，不等于 Android 冷重启后的实际 ZIP，不能升级 G5。
