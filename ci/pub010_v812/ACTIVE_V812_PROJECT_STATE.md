# 工作平台发布器｜唯一生效研发规范与当前故障节点

**生效规范：用户上传的《研发规范 V8.12统一源码维护版.zip》且仅此一版。**
核心规则唯一入口为该规范 `00_核心/execution/CORE_POLICY.yaml`（R001—R132），数值权威为 `DECISION_LIMITS.json`。V8.10.1 和更早规范仅作为历史证据，不作为当前命令或发布门禁。

- 原始产品：**独立 Windows x64 工作平台发布器 EXE**；正式工程 **V2.11.2.9 RC1** SHA-256 `e22ec4d346994d4494974974afdbabb11015076a11ffb58160a2b65b04c5b8bf`。三种发布模式与手选资源保持不变。
- 冻结原问题台账：PUB-001—PUB-036 **36项原编号保持不变，正式销项仍为0**。重点 PUB-010、PUB-027，涉及原定安装落盘与数据保护，不能因测试工具通过销项。
- 可继承证据：Windows Server 2022 上真实 V2.11.2.9 发布器生成34/28文件安装 EXE，两者独立载荷对账；首次28文件落盘及28→34→28升级成功。**非 Win7＋Excel2013 真机宏业务**。
- 已知缺口一：锁定旧 XLSM 导致真实安装 UIA 超时；旧自动化以错误的进程退出码3060作为预期，但安装器的 GUI WM_DESTROY 使用 `PostQuitMessage(0)`。应核对 **WF-3060 提示、关闭窗口和数据原字节不变**，而不依赖 OS 退出码3060。
- 已知缺口二：升级34→28后6个验收 CMD 被 `wf_v0384_preserve_user_data` 当旧版额外文件保留。**只能在有可证实的用户明确排除、文件来源和不误删约束时改变产品逻辑**；不能按文件名盲删，更不修改用户 Data。
- V8.12新增已验证：`pub027-v812-locked-file-minimal.yml` 原生 Windows 锁定文件返回 Win32 ERROR_SHARING_VIOLATION=32（1ms），回退旧文件和 SHA 校验通过；`pub010-v812-modal-diagnostics.yml` 原生 PID 窗口发现、跨进程排除和 UIA 确认通过；两者属于**独立专项**不等于原 PUB010/PUB027 完成。
- 最新进行中的真实 Win32 诊断仅使用 V2.11.2.9 未修改安装器 PE + 手工构造的**两文件纯合成 V6载荷**。此测试不用于证明发布器生成能力、真实业务 XLSM、Office 注册/宏及用户原定 G4/G5。
