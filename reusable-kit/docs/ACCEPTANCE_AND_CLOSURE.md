# 研发问题与销项闭环（可跨项目复用）

## 五步闭环
1. 建立原始问题清单：需求、失败、未运行、环境阻塞分别编号，锁定原验收标准。
2. 多路线检索：优先复用成熟开源实现和已验证工程，不因一条路线失败就降低需求目标。
3. 真实实验：实际编译、安装、启动、业务操作、退出重开及数据回读，区分模拟回归和实际宿主。
4. 独立证据：记下被测版本/哈希、运行环境、Run ID、日志、截图、输出文件校验值和独立脚本复核。
5. 只有满足原验收标准才销项；失败与未运行保留原编号并写出下一轮步骤。

## 状态
`NOT_RUN` 未做过；`BLOCKED` 环境或输入条件阻塞；`FAIL` 实验未达到标准；
`SUB_PASS` 某些子项有证据通过；`PASS` 整项全部验收要求通过。
不得以 CI 任务成功、静态测试通过、ZIP 能下载自动认定业务整项 PASS。

## 每次交接至少保存
- 通用方法、工具链及版本、脚本、命令、依赖
- 成功和带条件的失败实验
- 完整项目文件另行单独归档（本通用包只含方法和通用程序）
- 追加的原编号台账；不要重置已有记录
- 能从 GitHub Actions/Android AVD 等实际恢复的工作流与证据路径

## 数据安全
- 不提交正式私有源码到公共 CI。
- 临时 Runner 只保存待验收时需要的临时明文；正常结束及异常退出均清理。
- Git 同名覆盖不是安全删除，不列入流程。
- 不把明文、密钥、敏感日志或敏感输出复制到通用包。
